### G1：真实窗口观察桥及安全边界（约 1–4 小时）

主代理负责 `architecture/v2/host/NteHost.WindowMonitor/` 与 `architecture/v2/integration/` 的最小扩展，复用 A/B/C。

- 从原始事件产生/入队/丢弃位置提供真实的单调 revision、批次范围、未处理事件和溢出信息。先定义同一读取时点的一致性，避免快照与事件来自不同批次。
- 审查整个批次的连续性，包括批次中间跳号、乱序、重复。`IntegrationWindowObservation.HasGap` 目前主要检查端点，需用反例判断内部完整性由哪层负责，不能只看首尾一致就放行。
- HWND、进程实例、A generation、B focus epoch、C session 分别保留。相同 HWND 被复用时重新验证完整身份。
- 用户接管、失焦、pending、overflow、原始事件缺口或身份读取失败都拒绝动作；焦点回来不自动重新授权。
- 现有协议 1.0.0 不因宿主内部接口扩展而随意变更。确实需要跨进程变化时先列出现有契约不能表达的事实，再决定兼容范围；不得偷加私有字段。
- 分层验证：确定性离线反例 → 原生观察适配 → 受控窗口。真实观察源的测试使用真实回调证据；动作端可以保持 fake，但报告必须明确哪一层是真实、哪一层是假实现。

**闸门：**受影响的 I1 行为与有实际差异的缺口/竞态反例通过，其余引用旧证据，真实观察能提供可核验的来源信息。真实观察桥未通过时保持主动输入关闭；可继续独立的文件帧/Engine 工作，但不能称安全链已完成。

### G2：Host 真正传帧（约 2–6 小时，可与 G1 独立并行）

- 明确帧生产者、槽状态和 ACK 所有权；保留 V2-1 生命周期探针，新建或明确扩展实际帧生产模块，不通过放宽旧“零写帧”断言掩盖职责变化。
- 先让真实截图经 Host 写入 MMF，Python 只读映射。逐像素比较传输前后，验证 BGRA/BGR 转换、stride、尺寸、序号、session 和时间戳。
- 冻结格式保持 64 字节帧头、4 槽、BGRA8、协议 1.0.0。四槽满时丢弃新帧并计数，禁止强制覆盖消费者持有的槽。
- 支持无 ACK、错 ACK、旧会话 ACK、重复 ACK、消费者退出、坏帧头、部分写入和重新建图。消费者引用的内存不能在 ACK 后继续异步读取。
- 帧容量上限仍是 1920×1080；样本中有 2560×1440，G0/G2 必须调查数量。超限输入明确拒绝并记录，或提供有可逆坐标映射的显式缩放/ROI 适配；不得静默截断、改容量常量或误用裁图坐标。
- 原始高分辨率证据独立保留，禁止以预处理图覆盖原图。没有合法传递变换元数据的接口时先限定支持范围，不偷偷扩协议。
- 若真实情报需每帧先保留再慢处理，定义“可丢的显示帧”和“必须落盘的关键证据”不同处理，不能用最新帧策略丢掉短暂情报。

**闸门：**实际进程间真实像素一致、锁槽无覆盖、异常会话无串帧、错误计数可复算。只建图/打开映射不算通过。

### G3：真实 Engine 与最小业务投影（约 4–9 小时）

- 保留 `engine_ref`，新增真实 Engine 适配。加载真实 OCR、图鉴及状态恢复完成后才宣告业务就绪。

- 先展示现有协议可承载的场景、四席出价、局 ID、局状态和健康信息；投影以 Python 权威状态为准。缺少报价不是 0；窄协议里的整数字段不能强迫未知值变成已知事实。
- 现有 STATE_SNAPSHOT 是受限投影，不是完整 CurrentMatch 存档。完整状态保存在 Engine 一侧的隔离存储；Host 不用不完整投影反造原始事实。
- 只接本轮有明确校验的最小命令白名单。命令过期、旧会话、相同 ID 不同载荷必须拒绝；重发成功命令不产生第二次副作用。
- 一组固定真实输入分别走现有业务入口与 V2 入口；比对原始观察、接受字段、人工保护、归档结果。必须通过两条实际路径获取结果，不能复制期望值填输出。
- 不改现有估值数学核心；未知红、概率策略、Fast 或新匹配后端维持原资格状态。接入稳定后再决定独立优化任务。

**闸门：**真实 Host + 真实 Engine 的单次启动能显示真实结果、保留证据并写入隔离状态；无 mock 对局和手填识别结果冒充业务。

### G4：同局恢复、只读实时接入与故障矩阵（约 8–12 小时）

- 从引擎硬终止、先断管道、心跳异常、模型加载失败、文件暂不可写、迟到消息中选择本次改动真正影响且旧证据不足的路径，不机械跑全套。恢复必须先同步状态，再经过业务 ready gate。
- 一局 ID 在草稿、结算、退出、重启、导出/导入中一致；不出现幽灵草稿，不把下一局事实回写上一局。
- 有结算和归属证据才允许完成对应业务；没有真实本人获胜素材时该项保持未验收，不通过手工设置 acquired=True 代替实录。
- 逐色出售选择和值/来源原子一致；人工保护、事前预测与终局财务不能被晚到证据错误覆盖。
- 分别测进程检测、重启、模型初始化、状态同步、业务恢复。几毫秒的进程重启不得当完整业务恢复时间。
- G1 通过后接只读窗口捕获：目标验证、失焦/最小化、分辨率改变、捕获失败都有显式状态；没有游戏时可用受控画面证明捕获链，但报告标为受控窗口。

**闸门：**已实现范围内恢复和持久化一致，关键故障可复现、可恢复；真实游戏、受控窗口、录像回放三者范围明确。

### G5：长稳、性能和交付（约 11–16 小时）

- 先判断是否存在资源累积、队列增长或跨局生命周期的具体未解风险。没有该风险且本轮不做完整发布验收时，不启动长稳；有则针对该风险选择最短有效负载与观测窗口，证据足够即停止。跨版本时长不能拼接成同版本证据。
- 场景含多局切换、重复帧、短暂情报、无目标窗口和恢复。固定采样 RSS、句柄、线程、队列长度、帧丢弃原因、延迟和当前局 ID，保留原始数据及源码身份。
- 预热和稳态分开。P95 报样本数、计算方法、失败/超时和缺失数；建议每类≥100个有效事件，小样本只报 min/median/max，不假装可靠 P95。
- 沿用业务门槛：忙碌确认 P95≤0.5s，出价到实际显示 P95≤1.5s，情报结构化 P95≤2s。定义各指标起止点，同一 QPC 时域或有明确校准；只有控制台处理耗时不能替代 UI 展示延迟。
- 无界内存/句柄增长先定位，不能靠周期重启掩盖。给出预热后曲线、线性趋势和相同工作负载对照，明确异常阈值依据。
- 只生成一个当前试验候选。默认关闭的试验开关、启动、停止、依赖、数据位置和已知限制写在同一交付说明。
- 检查正常退出后的本次进程树；只处理本次启动的进程，不误杀用户的其他 Python/Node。
- 最后汇总本轮已完成的定向检查，不因到了交付环节再跑一遍。只有生产入口或带图迁移实际被修改且已有检查未覆盖时才补相应最小验证。

**闸门：**当前交付范围内的具体风险已有最小充分证据，可直接交付。未安排的长稳、真实游戏和跨电脑检查注明未验证，不因此无限扩展本轮任务或虚报通过。
