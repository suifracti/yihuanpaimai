# 键鼠场景识别与整局生命周期规范

依据：2026-09-08 用户的 14 张标注图及两段对局录像。仅支持键盘、鼠标；道具补货指补充本局消耗的品鉴仪器等道具。

## 调度规则

1. 每个识别周期只启用一个场景组。组内可包含多个互相核对的小区域，禁止同时跑所有场景 OCR。
2. 默认从大世界开始寻找。已确认场景优先复核自身；失败后顺序检查候选场景，直到恢复定位。轮询必须覆盖全部已支持场景，不能永久锁在某一步。
3. F5、Esc、点击、滚轮、拖动只改变检查优先级，不能直接确认场景或写入游戏事实。只接收游戏窗口前台的键鼠事件，坐标以游戏客户区为准，按 1920×1080 比例换算。
4. 场景图标/标题优先做小区域图像匹配；红点、数值、玩家头像、动态背景不得成为必需特征。文字 OCR 仅在当前组确实需要读取数值时运行。
5. 场景失配立即停止该组业务识别，保留最后已确认值及时间，不拿旧值冒充本帧结果。连续确认后切换；丢帧、黑屏、动画进入寻找状态。
6. 超时找不到支持的场景时，显示一次“未定位，请返回大世界或已支持页面”，继续低负载轮询，恢复后清除提示。不能把未知画面直接认作大世界。
7. 场景切换递增识别代次。旧任务完成时必须核对场景代次和对局 ID，不得把上一页面/上一局结果写入当前页面。

## 场景与下一步

| 场景组 | 确认依据 | 操作提示与后续组 | 本组允许读取 |
|---|---|---|---|
| 大世界 | 右上固定键鼠图标，忽略通知红点 | F5/左上入口 → 都市大亨；地图键 → 地图 | 场景状态 |
| 都市大亨 | 左上“都市大亨”标题 | 都市闲趣入口 → 闲趣；Esc/关闭 → 大世界 | 场景状态 |
| 都市闲趣 | 顶部“都市闲趣”标题，列表滚动不影响 | 滚动/拖动后点击 → 依次检查拍卖大厅、地图；关闭 → 地图或大世界 | 场景状态 |
| 地图 | 左下闲趣入口及右上资源图标组合 | 左下闲趣 → 闲趣；Esc/关闭 → 大世界；其他点击不推断进入拍卖 | 场景状态 |
| 拍卖大厅 | 左上“即刻落槌”及“我的信息”组合 | 开始匹配 → 匹配；场地/帮手/仪器 → 对应设置；关闭 → 返回导航 | 当前场地、帮手、仪器与可观察库存 |
| 设置/补货 | 对应面板明确标题；不能只凭点击确认 | 选择/补货后必须返回大厅核对实际结果；取消不算完成 | 当前面板的选中项、库存及补充结果 |
| 匹配 | 匹配中/取消匹配的明确界面证据 | 取消 → 大厅；成功 → 载入 | 匹配状态 |
| 载入 | 载入专属图像或进度区域 | 下一帧可能为局内或大厅，进/出方向由已确认上下文辅助 | 载入状态，不读情报和结算 |
| 局内 | 回合标题与竞拍界面组合 | 每回合情报出现才读中央；出价变化才读左侧；终局 → 结算 | 回合、情报、当前出价、实际道具使用证据 |
| 结算 | 结算标题，稳定账单另行核对 | 保存原图、完整仓库采集；离开 → 载入/大厅 | 稳定账单、仓库；不覆盖局内输入 |

## 道具与完整生命周期

结算账单完成和流程完成分开记录。流程为：准备 → 匹配 → 局内 → 结算 → 返回大厅 → 核对是否需要补货 → 补货完成/无需补货 → 可开始下一局。

- 配置了仪器不等于使用过；点击仪器不等于使用成功。由道具使用后的明确情报卡、库存减少或成功提示确认消耗。
- 确认使用后标记“需核对补货”，根据库存/配置界面判定实际缺货。不能仅因缺少证据就标记“无需补货”。
- 点击补货按钮不算成功；库存增加、补充成功提示或明确的恢复状态确认后才关闭补货事项。
- 中途启动或无法读取库存时保留“补货待核对”，不制造完成状态。跟踪用户操作，不自动购买道具。

## 验收要求

同时验证正常顺序、随机顺序、跳步、中途启动、返回、滚动后选择、黑屏、红点变化、窗口缩放、场景切换时旧任务回传。每帧记录活动组、匹配分数、已确认场景、寻找状态、耗时；正常导航不得调用全屏 OCR。截图上的教学红字不能作为识别模板。

本文件为实现约束，不代表所有场景已经实现或验收通过。每个组的实际支持状态以实现及录像验证结果为准。
