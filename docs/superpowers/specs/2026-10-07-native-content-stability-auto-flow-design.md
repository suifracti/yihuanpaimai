## 目标与当前真正的阻塞

交付目标仍是：大厅启动观察 → 对局连续观察 → 结算自动判稳 → SOURCE原页保存、指定窗口滚动、滚后原图与位移核验 → 完整或明确部分收页 → 返回后退役旧局、自然下一局继续。用户无需确认揭示结束、逐页操作或每局重新武装。拒绝和归档属于失败处理，不能替代正常路径交付。

当前存在三个相关阻塞：

1. 内容保护区没有可复用的完整语义覆盖证明。局部手工图案窗口会漏数量角标、文字、品质标记，底部物件又会被裁切。现有暗框规则不能识别所有揭示状态。
2. 原始逐像素相同太强；平均差、微变上界、回返、灰色按钮或识别一致又太弱。尚无验证过的内部渲染变化解释器，不能据现16图宣布稳定判据成立。
3. 当前揭示期间不断保存SOURCE，16张来源可先于稳定耗尽；`NativeWarehouseIntake.finish_manual_capture` 又把所有保存的descriptor交给后处理。未合格原图需要保留，但应与可支持覆盖的页明确分开。当前正式历史隔离条件不动，不据此宣称正式历史已被污染。

设计减少绕路的办法是一次完成“判据原型＋带保存的正常收页链”，而不是再出只会拒绝的判定器。生产接入以这两个检查的正常路径成立为前提；实机成功仍另外验。

## 一、保护整个可见内容，不靠手工物品窗口

复用当前 `warehouse_vision` 的网格测量和格子候选分割，提供窄的只读几何接口，不调用身份匹配、数量累计、估价或目录候选导入。现有识别算法/拆件成果不重写；需要接口调整时先核对共享文件基线，只提取接口增量。

每张同哈希原图生成一个 `content-profile`，明确区分：

- **完整可见网格保护域**：图案、所有潜在文字/数量角标位置、品质底色/框线、格线、空区、未显框，以及底部/边缘裁切处的可见像素。分割用途是解释/定位变化，不能把未识别的格子或像素挖掉。所有保护子域的并集必须覆盖整个可见网格，没有“只比已识别物品”的洞。
- **外部装饰**：只有几何定位证明位于网格外的背景、品质筛选条、估价等界面区域可排除于内容支持。位于物件/网格内的光效不能仅凭称作光效而排除。
- **按钮**：文字存在与 LIGHT/GREY/UNKNOWN 外观分别报告。外观只是动画线索，不能单独证明启用/禁用、揭示完成或滚动资格。
- **滚动观察域**：原大ROI保留，用于滑块、图像位移与重叠，不能用“内容支持”替代它。

每个格子/区域只输出观察类别：有可见图案、未显/揭示证据、可证空区、裁切片段、未知。不能因未检出暗框就变成已揭示。

**裁切处理**：保护可见部分，记录 `PARTIAL_OBJECT`，不认定完整身份/数量/占格。可见部分取得合格稳定支持后允许滚动去取得邻页；跨页重叠和未裁切支持能核对后，才由原账本判断关联及覆盖。若要求每个底部物件都先完整才滚动，流程会自锁，本方案不采用该条件。可见网格自身定位/覆盖不完整或被遮挡则不能滚动。

## 二、建议只试一个可检验的内部变化解释路径

改变的合同是“全部可见内容相关结构有独立支持、所有内部差异得到受约束解释”，而非“全部RGB字节相同”。原图和差异不修改，原严格模式保留；交付时序观察模式运行中不切换、不自动降级。

需要区分的真实内容变化是：物件/图案出现或消失、揭示闪光和暗框转图案、文字/数量字形改变、品质框/标记改变、物理边界或占格改变、新遮挡及滚动。每项都必须有正反例；不能只用物品名称OCR一致作为证据。

建议的最小判定器是两个互相独立的检查同时成立：

1. **全网格结构检查**：逐格记录可见图案结构、字符/数量候选字形、品质框与占格边界；空区也检查新成分。用原始像素提取位置、局部对比关系、轮廓/连通结构；不得对原图先平滑/量化来消除差异。低对比度新字符仍是变化或未知，不能因其幅度小而忽略。无法覆盖/解释的区域仍UNKNOWN。
2. **受约束的渲染解释检查**：先固定只试“共同的微小亚像素采样相位”这一假设，检查原始相邻像素的空间依赖是否能解释后段变化。参数只由多个事先指定、互相分离且通过几何/内容检查的参照区估计，不用待保护的文字/物品变化反过来拟合自己；再在所有保护像素及留出参照区验证。禁止按物品各拟一套颜色曲线、忽略不合模型的像素、用全图平均残差放行。

渲染解释器不生成一张“消差后的原图”替代证据；记录原图哈希、原始差向量、模型参数、参照区及每个不能解释的像素。模型的合法参数范围、整数输出范围必须来自独立的已知渲染/采样约束和对照，不从这批1～5级变化倒推容差。

这是**待验证的模型假设**，不是已定位的WGC错误，也不保证适配实际游戏。上一轮严格颜色查表已出现矛盾，因此不再拟合全局亮度/颜色查表。若这一固定模型不能解释现有留出帧并拒绝字符/数量反例，就报告失败及残差，不能继续换几十种滤波/阈值凑通过。

模型检查通过仍不能单独放行：结构、揭示/遮挡状态、局次/窗口/映射/原图、独立交付和期限等必须同时成立。支持证书明确写 `CONTENT_STRUCTURE_SUPPORTED`，不写来源严格新鲜度或请求后渲染通过。

## 三、避免揭示耗光来源额度，保持SOURCE先保存

复用既有观察FRAME、Engine串行处理、最新一帧背压和 `WAIT_STABLE`。不改普通FRAME选择器、不建第二采集线程/队列、不另开常驻录屏或保存普通FRAME绕过SOURCE预算。

- 首次观察结算即固定原70秒截止，本局一次领取现有任务；可保存一张初始原图作为本局证据。
- 揭示期间，既有已接纳FRAME的轻量全网格/揭示提示只决定何时值得请求SOURCE。提示带同局次、同窗口/映射和捕获身份；过期/迟到提示不用。它不能授予稳定、滚动或正式事实。至少600ms节流，已有请求不叠加；没有提示也不刷新70秒。
- 首次候选成立后显式请求SOURCE：**先按现有v2保存原BMP/PNG并核对哈希，再对这张原图做完整判定**。此前观察提示不能代替它。
- 第一次完整候选原图仅建立新锚点；之后由下一次独立SOURCE支持验证，不能拿最初尚未揭示的锚点来证明最终稳定。复用 `_support_floor`、租约、计数及现有定时器。
- 两张独立原图均完整合格、同视口且全部门禁通过，才产生稳定证书并调用现有滚动入口。画面仍揭示/结构变化则继续在原预算内等待；UNKNOWN解释错误、作用域失效或不可证明几何则结束，不通用重试。

预筛是节省来源槽的提示，不是新的捕获合同。所有显式SOURCE尝试仍消费原32次请求，写出的不同原图仍消费16张来源；保存失败也按原规则计费。实测可能因来源槽、请求、字节或70秒不足而部分结束；16张来源从来不保证16个视口。

## 四、贯通保存、稳定、滚动和覆盖

复用现有路径：

`SOURCE v2落盘 → _read_page同原图校验 → 全保护域与内容支持证书 → request_scroll_down → 指定窗口发送回执 → 独立滚后SOURCE落盘 → 滑块向下＋图像位移/重叠 → 新视口独立判稳 → 下一次滚动 → 已证BOTTOM/NO_SCROLL＋首尾/重叠账本 → 完成或部分结束`。

关键增量：

- 原图保留角色：`UNQUALIFIED_OBSERVATION`、`STABLE_ANCHOR`、`STABLE_SUPPORT`、`POST_SCROLL_PENDING`。角色只更新元数据，不修改原图；证书绑定原图哈希、捕获ID、局代际、观察会话、窗口实例及映射。
- 后处理只将具备合格内容支持与视口关联的代表页交给现有覆盖/物理账本。支持帧不算新增页；揭示/未知原图继续在证据索引保留，不能混进覆盖链或累计数量。
- 滚动发送结果拆开记录资格、是否发送、返回/错误、滚后原图。消息成功绝不表示滚动成功。无进展、滑块未知、反向、图像重叠未证或目标改变按既有门禁结束，保留部分材料。
- 顶部缺失、最后未到底、链路断裂或裁切片段未关联，不能COMPLETE。底部完成仍由原Coverage Ledger判定，不用原图数/框数代替。
- 取消、退出结算、跨局/窗口/映射改变撤销现有任务代际与SOURCE。旧证书、计时器、原图回调和后处理结果不能归入下一局。
- SOURCE材料仍不提前产生正式身份、数量、价格、账单冻结或正式历史事实。

## 五、必须同时通过正常与异常的最小离线端到端检查

使用同一生产收页器/SOURCE协调器/intake/原图存储/滚动观察与账本，仅WGC交付和窗口发送端使用有限的离线适配器；不能把 `_read_page`、内容判断和覆盖直接补丁成成功。真实WGC/消息效果仍明确未验。

| 用例 | 必须观察到的行为 |
| --- | --- |
| 揭示→有渲染变化但内容一致→自动收三视口到BOTTOM | 初始证据、候选锚点及独立支持落盘；自动滚动继续；滚后原图有滑块/图像位移和连续重叠；账本COMPLETE；支持帧不重复计页；原截止和计数不刷新 |
| 图案/文字/数量/品质/占格的局部真实变化，包括低幅变化 | 不能形成稳定支持或发送滚动；不是仅名称OCR一致就通过；后续真正独立稳定时可恢复同一WAIT_STABLE候选验证 |
| 同内容，仅网格外背景变化 | 正常形成内容支持并继续正常收页，但其余滚动资格仍需独立通过 |
| 消息成功但视口没变、滑块变但图像重叠未证 | 不计页/覆盖，明确停止原因；保留滚前后原图 |
| 保存失败/原图被修改 | 无稳定证书、无滚动；失败计数和材料保留 |
| 稳定后取消、窗口/映射/局次改变、旧回调/后处理迟到 | 立即结束旧任务；无旧滚动/结果发布；下一局使用原生命周期，旧原图不混入 |
| 原70秒、16来源或32请求耗尽 | 在原边界结束并保留部分；失败和重复请求照常计数，不重新OPEN/自动补采 |
| 返回大厅并自然进入下一局 | 原局退役、计时器/租约释放；下一局按既有代际再自动触发一次，不手动重新武装 |

合成夹具的语义真值由独立图元/字形定义，不由被测判定器输出生成。已保存原图作为真实揭示拒绝和模型留出材料。正常路径必须真实经过保存与资格/位移/账本，不能只增加拒绝用例或用完成数量猜COMPLETE。模型正常例若仍永远未知，就不接生产并直报算法阻塞。

## 六、最小新增证据，一次安排而非反复开局

### 无游戏输入的离线新增材料

独立生成同一个完整网格的三组原始夹具：同内容/已知渲染相位变化，文字/数量/品质/图案局部变化（包括1～5级低对比度变化），多视口滚动带裁切物件和首尾/重叠。同时包含无数量角标与有角标。用于区分“共同渲染变化”与“局部真实内容变化”、以及“裁切片段”与“完整物件事实”。不改变16张真图，不采自建窗口/桌面。

### 确认后的单轮真实完整流程

在离线正常收页成立之后，仅安排一次：大厅提前启动→一局→结算自动收页→返回。用户只正常游戏，不需确认揭示结束或手动收页/滚动。

| 需留证状态 | 要区分的问题 | 原预算内最小材料 |
| --- | --- | --- |
| 本局结算刚出现/揭示期间 | 真实揭示与预筛是否耗尽SOURCE、是否提前滚动 | 至多1张初始SOURCE；普通FRAME只留既有事件/候选诊断，不新增永久原帧序列 |
| 候选完整可见内容及独立支持 | 全保护范围/渲染解释是否适用于实际新场景，非只匹配旧16图 | 2张合格SOURCE及同哈希证书，通常1～5秒内完成；时长不是放行条件 |
| 首次滚动后及支持 | 消息发送与真实位移、重叠、裁切补齐是否一致 | 2张滚后SOURCE、API回执、滑块/图像位移与顺序证据，通常1～5秒内完成 |
| 后续视口到末尾 | 多页完整覆盖还是只是部分 | 使用剩余原16张来源/32请求，首次结算后最多70秒；不留新预算 |
| 返回/下一局 | 退役和跨局换代 | 返回状态；自然进入下一局才验下一局，不发生则未验 |

70秒从首次观察结算固定，包含揭示等待、保存、判稳和滚动；上述1～5秒仅工作估计，不是固定等待、时间保证或追加期限。完整验收的观察上限拟为一局至返回，再最多30秒看是否自然进入下一局；没有下一局就结束并标未验，正式产品持续会话仍用既有停止入口。

有资格/身份/映射/取消/未知错误或预算失败立即结束该次收页，保留实际证据，不换模式、不自动重启或追加取证。是否继续正常大厅观察遵守现有生命周期和本轮验收终止策略，不偷偷重新收同一局。

## 七、修改范围、确认与交付

拟新增窄内容证据模块（全网格保护、局部结构和受约束渲染解释），修改：

- `app/native_warehouse_content_stability.py`、`app/native_warehouse_reveal_marker.py`：新的证据分层，严格模式不变；无自动按钮输入。
- `app/native_warehouse_auto_capture.py`：复用WAIT_STABLE等已有阶段、定时器、租约和预算；预筛请求节奏、证书绑定、正常收页接线和明确未知结束。
- `app/native_warehouse_intake.py`／必要的SOURCE协调器元数据：稳定页角色、代表页选择及原图/作用域复核；不改Host预算或来源时间戳合同。
- `app/main.py`、Engine既有Native观察回调：仅加同作用域的轻量候选提示，不重写采集、MMF、队列或生命周期。普通FRAME不是最终页面证据。
- 已有网格算法的窄只读接口（若确实必要），与当前dirty基线协调；不重写拆件、目录或身份算法。
- 对应内容/收页行为测试、独立小型夹具及来源说明。原BMP/录屏、大日志和build产物不拟入库。

阶段顺序：**先固定语义保护和单模型原型→同入口离线正常收页与拒绝/停止端到端→通过后接生产增量并编译→报告候选→明确“开始”后单轮完整实机**。阶段失败报告哪个正常节点不能成立；不得把“安全拒绝”写作功能完成。

用户已确认本轮离线实现、观察FRAME只作预筛和合格页角色筛选。生产入口启用仍以判据适用和正常收页通过为前提。若固定模型不适配，则真实自动判稳仍是具体阻塞，不能用人工确认/手动收页替代。当前离线结果见 `docs/reports/2026-10-07-native-content-flow-offline.md`。
