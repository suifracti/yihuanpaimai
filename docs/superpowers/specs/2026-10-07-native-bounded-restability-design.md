# Native 原预算内重新判稳设计（待确认生产接入）

基线：50d6ae8 + retained-boundary/3971ddcff33d + source-auto-eligibility/3632aef624b8 + bounded-postclose-trigger/321cf05b5e76 + scroll-content-diagnostics/55d04960a506。
反例：build/native-scroll-stability-20261007/lifecycle-real-01/real-result.json。取得两张同一 TOP 视口的原图，揭示动画仍显示，内容门禁拒绝后结束；滚动接口没有调用。当前生产候选不改，本设计和原型尚未接入生产。

## 控制合同

复用 NativeWarehouseAutoCapture 的 WAIT_STABLE、现有 SOURCE、串行事件处理和可取消定时器。不重新 OPEN，不重走 confirm/start，不重新武装，不新建局状态机。保持首次观察结算时固定的 Host 截止，本地只取更早的截止；重判不得把截止改成“现在 + 70秒”。

所有初次、支持、重判、滚后和失败的显式 SOURCE 请求使用同一现有计数：Coordinator 的 requestOrdinal/_ordinal 与 Host 的 _attempts。拟在 source_session_snapshot 增加只读 requestAttempts，不新增第二套请求预算。重判前最多32次请求、最多16张来源、剩余原图/PNG字节预算及截止仍须合格。Host 保持最终预算权威。完全相同的新交付仍消耗请求次数，不新增来源页，也不认定覆盖。

每次重判至少600ms节流，仍需下一次独立交付证明：同观察会话、同池代际、捕获ID不同、序号递增、来源标记递增、请求晚于上一支持读回至少250ms、有效交付期限及原图绑定。600ms只控制请求节奏，不是放行条件。仍最多一张待处理，已有请求未完成不叠加下一次，保持既有5秒请求期限。

不按600ms连续消耗动画原图：重判间隔为 max(0.6秒, 剩余截止时间 / (2 × min(剩余来源槽, 剩余请求次数)))。用剩余时间的一半均摊最坏情况下的可请求量，给后续稳定支持和收页留时间；数量或字节不足时仍停止，不额外留出新预算。不同原图也消耗来源槽，重复交付只消耗请求次数。每次从同一个固定截止算剩余量，不重置截止；实际OCR/响应耗时可能使期限先到。间隔仅决定何时请求，时间流逝本身没有任何稳定/覆盖放行权。这是预算内的保守采样策略，不能保证捕捉每个动画步骤，也不能保证足够资源完整翻页。

## 可以继续的唯一内容分支

| 证据 | 行为 |
| --- | --- |
| 同视口、有效独立帧，内容ROI像素确实改变 | 明确“尚未稳定”，替换比较锚点并请求下一独立帧；不滚动、不认定覆盖 |
| 同一已校验原图中，指定结算按钮的“跳过动画”文字形状匹配 | 明确界面仍提供揭示动画操作；即使像素暂时相同仍等待独立帧；不操作按钮 |
| 标记刚从 PRESENT 变为 NOT_DETECTED | 仅作候选过渡；再取得新的独立支持帧，不立即放行 |
| 静止的未显/未知物框，没有明确动画标记或内容变化 | 维持 CONTENT_UNREVEALED_OR_UNKNOWN 终止，不能因“可能是动画”重试 |
| 身份、局代际、窗口、映射、场景、停止、截止、独立性、文件/hash、几何、读回或请求失效 | 立即沿已有停止路径结束，保留部分证据；没有通用异常重试 |

“跳过动画”检测使用已有原图的局部文字形状锚点，仅增加正向揭示线索。模板缺失、读取异常、不支持的几何、非有限得分为未证明错误，停止；NOT_DETECTED 不等于动画完成。拟使用与当前结算标题一致的形状匹配方法/0.88分数下限；这不是来源时间容差。离线只核对两张既有真实原图中的标记和一个清除文字的负对照，未证明所有分辨率、UI主题或类似按钮的识别准确率。

## 放行及安全边界

只有动画标记未检出、没有未显/未知轮廓、同视口的两次独立交付ROI像素严格一致，且所有既有 SOURCE 和滚动资格均合格，才进入既有稳定分支。标记消失或计时结束均不能独立放行。保留原有本局一次、跨局换代、图像位移+滑块变化联合门禁、正式身份/数量/价格/记账条件。

逐次更新“最后已核对支持捕获ID”作为递增下限，防止后续事件重复用旧支持帧。它与“用于保存/发送的原图捕获ID”分开：滚动命令的 savedCaptureId 仍绑定实际保存原图，stableCaptureId 绑定新的支持交付；Host 的 saved/prior-saved proof 仲裁不改。新鲜的 DUPLICATE_PAGE 可证明同一原图像素交付，不能增加视口或翻页进展。

取消、窗口失效、映射失效、局切换、观察退出与截止不进入内容重判。复用现有 SOURCE 撤销及任务 generation 取消旧定时器/回调，不让旧局结果写入下一局。正常停止后关闭当前收页任务，不重新尝试本局。部分原图仍是本局证据，不提前形成账单事实。

## 拟修改范围

- app/native_warehouse_auto_capture.py：只在明确内容分支重入 WAIT_STABLE；更新锚点/支持下限，检查原计数及截止，记录重判原因/捕获ID/计数/剩余时间；不把所有 _stop 包装成重试。
- app/native_warehouse_source.py：source_session_snapshot 只读暴露现有请求计数，原计数位置和Host合同不变。
- app/native_warehouse_content_stability.py 或单独的小型结算揭示线索模块：增加与原图绑定的正向动画标记；现有内容资格不放宽。
- assets/scene_anchors/ 的小型文字裁图及来源说明：只含按钮文字，来源为本轮既有原图及哈希，不含UID、私人路径或物品身份标签。
- 相关算法之外的收页控制用例：把通过的离线原型场景迁入维护测试，验证增量；不动 core/warehouse_vision.py，不重跑旧完整矩阵。

原严格模式不变，运行中不切换/降级。Host无需重写帧选择、SOURCE保存、滚动协议、生命周期或预算。离线原型以继承方式验证当前收页器的控制行为；确认后在上述现有方法内合并增量，不把原型子类接成第二套生产入口。

## 离线判据与交付边界

原型及用例：build/native-bounded-restability-20261007/proposal.py、test_proposal.py、test-results.json。

- 最终结束的动画：静止但标记在/内容变化/标记消失期间0滚动；最终独立稳定支持后才请求1次滚动，不宣称实际位移或完整覆盖。
- 始终不稳：同任务在32次请求、16张来源或原70秒任一先到处结束，计数和截止不重置；部分原图保留。
- 取消和跨局：终止待判稳，旧定时器和迟到回调不能再请求/滚动或归入下一局。
- 未知错误、静止未知框、重复支持ID、失败请求、未知标记/计数及身份变化：立即终止，失败请求计数；不普遍重试。

这证明离线控制合同可实现，不证明新的文字锚点全场景准确率、真实揭示结束后的稳定判定或滚动效果。动画可能超过16张来源/32次请求/70秒预算，届时必须部分结束；严格像素相等仍可能因持续装饰动画始终不满足。WGC交付合同仍不能证明请求后渲染和来源绝对年龄，来源未来值问题没有修复。
