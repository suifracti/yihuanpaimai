> 目标：把当前“估值器”升级为真正的“拍卖决策系统”。
>
> 本文是当前阶段的**完整规划基线**。后续 Codex / GPT 执行时，应以本文为方向约束，不应擅自回退到已经否定的方案。
>
> 核心原则：

# 一、当前已经确认的核心结论

## 1. `NO MATCH → 保存后却出现估值` 是严重数据链路 Bug

当前存在这样的错误路径：

```text
严格 State Solver
→ NO MATCH
→ 页面仍把 no-match analysis 写入 currentAnalysis
→ 保存时只判断 currentAnalysis 是否存在
→ predictionSnapshot() 又重新调用 workingDecision()
→ 使用空候选 / 低信息 / 历史 fallback 生成一个金额
→ 保存出“看起来正常”的正式 prediction
```

所以：

```text
保存后能算
≠
严格求解恢复正常
```

实际是：

```text
严格求解失败
+
保存层偷偷产生 fallback prediction
```

这是 **P0 级 Bug**。

---

## 2. 15:53 这局必须成为永久回归测试

已知输入：

```text
Q = 9
P = 5
GoldAvg = 33538
KnownGold = 51077
KnownPurple = 18075 + 8128
Rounding = floor
```

这组输入不应该 NO MATCH。

至少存在：

```text
51077 + 37558 + 11981 = 100616

floor(100616 / 3) = 33538

=> G=3 / P=5 / R=1
```

还存在：

```text
51077 + 37558 + 30211 + 15309 = 134155

floor(134155 / 4) = 33538

=> G=4 / P=5 / R=0
```

而结算真实 State 恰好是：

```text
G=3 / P=5 / R=1
```

因此以后任何版本只要这组输入重新得到 `NO MATCH`，应自动判定测试失败。

---

## 3. Claude “recommendedMaxBid 历史胜率 83%” 的回测方法是错误的

错误回测：

```text
profit = actualTotal - recommendedMaxBid - cost
```

只要结果 > 0，就认为：

> 如果当时按 recommendedMaxBid 出价，就赚钱。

这个反事实不成立。

因为真实拍卖还存在：

```text
clearingPrice
```

如果：

```text
recommendedMaxBid < clearingPrice
```

那么你根本拍不到。

例如：

```text
recommendedMaxBid = 31.8W
clearingPrice = 40W
actual = 40.33W
cost = 5.5W
```

错误算法会算：

```text
40.33 - 31.8 - 5.5 = +3.03W
```

然后记成“推荐价获利”。

但现实是：

```text
只出 31.8W
→ 箱子 40W 成交
→ 根本没买到
→ 实际只亏情报成本
```

所以**绝对不能**在 UI 上展示这种“83%历史胜率”来建立错误信心。

---

## 4. 当前推荐上限混淆了“进入成本”和“追价决策”

现在的 `recommendedMaxBid / balancedCap` 逻辑会把当前 `cost` 从推荐价中扣掉。

这对于：

> 还没花钱之前，这局值不值得进入？

是合理的。

但当：

```text
5.5W 情报费已经花掉
```

这部分已经是沉没成本。

此时你要决定的是：

> 从现在开始，多出 1W 是否值得？

不能继续把已经花掉的 5.5W 再从“边际追价线”里扣一次。

因此：

**进入决策** 和 **已经进入后的追价决策** 必须拆开。

---

## 5. 红色重复上限必须继续是 `repeat=2`

不能采用：

```text
RED_MAX_REPEAT = 1
```

真实数据已经出现：

```text
300000 * 2
```

同一红色藏品重复两件。

所以：

```text
red repeat = 2
```

是当前真实数据支持的规则。

---

## 6. 不增加没有实战来源的 `redAvg`

目前实战流程中没有稳定“红色均价”情报来源。

所以不要为了算法完整性新增一个用户根本拿不到的输入。

---

## 7. 不把真实 5W / 5.5W 成本改成 2.5W

当前真实体验：

```text
达芙蒂尔一局约 5W 起步
+
入场成本
≈ 5.5W
```

不能为了让回测更好看，把默认成本改成 2.5W。

账本必须忠于现实。

---

## 8. 不因为几局低估就立刻写死新 heuristic

暂时不要直接上线：

```text
Q >= 15 → low tier 每件 +8%
```

也不要直接：

```text
minRed >= 2 → 红色估值切到 RED_TYPICAL_HIGH
```

这些可以做**实验分支**，但不能直接覆盖正式模型。

必须 strict walk-forward 验证后再决定是否晋升。

当前：

```text

↓

↓

```

目标：

```text
Observation / 实时情报
        ↓
Constraint Solver / 硬约束求解
        ↓
Feasible States
       ↙       ↘
State Probability   Value Model
       ↘       ↙
整仓价值分布 V
        ↓
Market Model
        ↓
市场成交价分布 C
        ↓
Decision Engine
├─ Entry：值不值得进入
├─ Intel：还值不值得继续花情报
├─ Global Profit Line：整局盈利线
├─ Target Profit Line：目标利润线
└─ Marginal Chase Line：边际追价线
        ↓
真实结算
        ↓
Strict Walk-forward Replay
        ↓
State / Value / Market / Decision 四层复盘
```

# 四、P0：Solver 状态机重构

## 目标

彻底解决：

```text
NO MATCH
timeout
低信息 fallback
输入过期 stale
```

被混成一回事的问题。

---

## 1. 新增正式 solverStatus

推荐枚举：

```text
valid
incomplete
fallback
no-match
timeout
stale
```

### `valid`

完整求解完成，并得到至少一个合法 State。

```text
solverStatus = valid
```

允许：

- 正式 v0.5
- Shadow
- 推荐线
- 回合快照
- 正常保存

---

### `incomplete`

搜索已经找到合法 State，但因：

- 时间预算
- 组合数量过多

提前停止。

含义：

> 已知这些 State 合法，但不能保证候选集合完整。

允许：

- 预览估值
- 标记低可信度

不建议：

- 正式推荐最高追价
- 用作高置信度训练样本

UI：

```text
候选搜索未完成
已找到 17 个合法结构
当前结果仅作预览
```

---

### `fallback`

不是矛盾，而是信息少。

例如：

```text
只有 Q
只有 Q + P
只有很少的公共情报
```

可以主动走：

```text
Low-information Baseline
```

这是合法工作模式。

必须和 `no-match` 区分。

---

### `no-match`

完整搜索已经确认：

> 当前硬约束组合不存在。

要求：

```text
estimate = null
recommendedMaxBid = null
probabilityProfile = null
```

可以保存：

```text
conflictSnapshot
```

但不能生成正式 prediction。

---

### `timeout`

Worker 超时。

含义：

> 没算完。

不能解释为：

> 无解。

UI：

```text
计算超时
没有证据证明当前输入矛盾
```

---

### `stale`

用户修改了任何会影响推演的输入，但还没重算。

此时旧结果仍可视觉保留，但必须覆盖提示：

```text
当前结果已过期
请重新推演
```

并禁用：

- 正常保存 prediction
- 正式推荐
- 当前回合自动冻结

# 六、P0：保存逻辑必须改成“复制预测”，禁止重新估值

正确架构：

```text
runCalculation()
↓
产生 FrozenPrediction
↓
保存 FrozenPrediction
```

错误架构：

```text
保存
↓
重新 workingDecision()
↓
生成新的 prediction
```

必须取消。

---

## 保存时的规则

### valid

保存：

```json
{
  "solverStatus": "valid",
  "prediction": { ...冻结结果... }
}
```

---

### fallback

保存：

```json
{
  "solverStatus": "fallback",
  "prediction": { ...低信息结果... }
}
```

但必须标记：

```text
confidence = low
```

---

### no-match

保存：

```json
{
  "solverStatus": "no-match",
  "prediction": null,
  "conflictSnapshot": {
    "inputs": {},
    "roundingAudit": {},
    "catalogVersion": "...",
    "solverVersion": "..."
  }
}
```

---

### timeout

保存：

```json
{
  "solverStatus": "timeout",
  "prediction": null,
  "partialStates": [...]
}
```

---

### stale

不允许直接作为正常 prediction 保存。

必须提示：

```text
输入已变化，请先重新推演。
```

如果用户坚持保存结算：

```text
保存 settlement
但不生成当前轮 prediction
```

# 七、P0：Worker 性能与超时方案

## 不要给每个 search 单独 5 秒

正确方式：

```text
一次 Worker 请求
→ 一个统一 deadline
```

例如：

```text
内部预算：8 秒
外部硬超时：12～15 秒
```

---

## Worker 应返回

```json
{
  "solverStatus": "valid | incomplete | no-match | timeout",
  "states": [],
  "searchCompleted": true,
  "elapsedMs": 1234,
  "truncated": false
}
```

---

## 判定规则

```text
states > 0 && searchCompleted
→ valid

states > 0 && !searchCompleted
→ incomplete

states == 0 && searchCompleted
→ no-match

states == 0 && !searchCompleted
→ timeout
```

这条必须严格。

# 十六、Global Profit Line：整局盈利线

回答：

> 从整个对局账本来看，最多拍到哪里还能不亏？

概念：

```text
Global Profit Line
=
Risk-adjusted Value
- 已发生总成本
- 未来确定成本
```

例如：

```text

成本 = 5.5W

```

---

# 十七、Target Profit Line：目标利润线

你实际并不满足：

> 只赚 5000 也算成功。

所以增加：

```text
目标利润
最低 ROI
```

例如：

```text
目标至少赚 3W
```

则：

```text
Target Profit Line
=
Risk-adjusted Value
- 全部成本
- TargetProfit
```

---

# 十八、Marginal Chase Line：边际追价线

回答：

> 已经花掉5.5W以后，从“现在开始”还值得追到哪里？

沉没成本不能再扣。

概念：

```text
Marginal Chase Line
=
Risk-adjusted Value
- Future Incremental Cost
```

例如：

```text
价值 = 70W
已花成本 = 5.5W
后面没有新增成本
```

则：

```text
Global Profit Line ≈ 64.5W
Marginal Chase Line ≈ 70W
```

解释：

```text
<64.5W
整局仍盈利

64.5W ~ 70W
整局利润可能被吃光
但从“现在”继续追仍比直接放弃有更高边际价值

>70W
从边际上都不值得继续
```

## 4. 核心交互原则：旧结果不要瞬间消失，但必须明显变 stale

在 15 秒倒计时实战中，输入新情报后右侧突然白屏或变成 Loading 菊花图会严重破坏玩家的认知连续性。

交互规范：
1. **输入改变时**：旧结果不立即清空，但数字整体降低透明度（0.4~0.5）并叠加半透明遮罩与徽标：
   ```text
   72W
   旧结果 · 正在根据新情报更新…
   ```
2. **新结果返回时**：解除遮罩与透明度，刷新为新数值并短暂微动效高亮：
   ```text
   86W
   已更新
   ```
3. **若 Worker 超时 / 冲突**：
   ```text
   上一结果：72W
   已过期，最新情报计算超时
   禁止依据旧结果追价
   ```
这样既不会导致界面闪烁空白，也不会误导用户把旧结果当成最新预测。
